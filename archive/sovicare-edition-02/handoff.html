What you build from.

Five sources, in this order. Figma wins on every visual value; brand-rules.md wins on compliance and wording. If this hub and Figma disagree, the hub is wrong: report it as a QUESTION.

  1. tokens/tokens.json and brand.css

    Every colour, size, space, radius, shadow, duration and easing. brand.css is generated from tokens.json. Link it first, never edit it, never hard-code a value it holds.

  2. components.css · reference components

    Buttons and their hover matrix, links, fields, answer options, cards, chips, step numbers and the overlay surface. Port the rules, not necessarily the class names. Specimens: Components.

  3. Figma h7D0 frames

    Layout, content and hierarchy for each page. Node links are listed under Figma frames. Read with Dev Mode; colours and text show variable and style names.

  4. Motion cards on Motion

    The 24-card M-set (M-001 to M-024) is the only motion reference. Every card uses --motion-* tokens.

  5. The rulebook

    Rulebook & decisions (same text as brand-rules.md): rules R-01 to R-83, the decision log, the exceptions log and open items. Cite rules by ID in tickets.

Prefer semantic tokens.

Use --color-text-*, --color-surface-* and --color-line-* where they exist. Use --color-brand-* only for brand surfaces, shapes and button fills.

Reduced motion comes with the tokens.

brand.css sets every --motion-duration-* and distance to 0 under prefers-reduced-motion: reduce. Script-driven motion must check the same media query.

Fonts.

DM Serif Display and Inter 400 to 700 from Google Fonts, with display=swap. No other face, except a monospace on internal screens.

A value is missing.

Do not invent it. Raise a QUESTION. The answer becomes a decision and a token before it is built.

How a change reaches developers.

One path, always in this order. A value you see in Figma is not ready to build until it has a token and a changelog entry.

  1. Figma h7D0. Avi changes the design. Figma is where every visual value starts.
  2. Decision. The change is logged in the decision log with an ID, date and owner. Wording and compliance changes are written into brand-rules.md in the same step.
  3. Tokens. tokens/tokens.json is updated and brand.css is regenerated with python3 -I tools/build_tokens.py. components.css is updated if a component changes.
  4. Changelog entry. The changelog lists the date, the decision IDs, the tokens that changed and the pages affected.
  5. Release. python3 -I tools/check.py prints 0 problems. Developers pull the new tokens.json and brand.css and run the release checklist on the affected pages.
No silent mismatches.

If Figma, the hub and the build disagree, raise a QUESTION the same day. Never copy a value from Figma by eye when a token exists, and never build a value that has no token.
